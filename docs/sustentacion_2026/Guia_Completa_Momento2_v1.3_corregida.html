Las 10 ideas clave (si solo te llevas esto, ya puedes defender)

  1. HTML es el esqueleto: etiquetas que dicen qué es cada cosa (título, párrafo, formulario, tabla). No es un lenguaje de programación.
  2. CSS es la presentación: colores, espacios, bordes, tipografía, posición y adaptación a pantallas.
  3. id es único; class se repite. El id identifica una sola cosa; la clase agrupa muchas.
  4. div es una caja sin significado; section es una sección con tema y título. Usamos section cuando el bloque tiene sentido por sí mismo.
  5. El modelo de caja explica por qué un elemento ocupa más espacio del que parece: contenido, padding, borde y margen.
  6. Flexbox alinea elementos en fila o columna; el grid de Bootstrap es Flexbox disfrazado de clases.
  7. Bootstrap es una caja de herramientas: CSS y componentes ya hechos (navbar, carrusel, tarjetas, modal) que se activan con clases.
  8. El JavaScript de Bootstrap es lo que hace funcionar el carrusel, el modal y el menú móvil. Sin él, son solo cajas bonitas.
  9. SQLite es una base de datos en un archivo: no necesita servidor. El formulario envía datos, Python los guarda y la página los vuelve a mostrar.
  10. La IA es una herramienta, no la autora. La usamos para prototipar; verificamos, entendimos y reconstruimos. Eso es la auditoría que pide el profesor.

Parte 2 · HTML desde cero

HTML es el esqueleto de la página. No es un lenguaje de programación: no tiene ciclos, ni condiciones, ni variables. Es un lenguaje de marcado: escribimos etiquetas que le dicen al navegador qué es cada cosa. El navegador lee esas etiquetas y construye el DOM (el árbol de elementos que vemos en DevTools).

2.1 La estructura mínima

Todo archivo HTML5 empieza igual. En VS Code se escribe ! y se presiona Tab; Emmet genera esta plantilla:

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>ProGanado — Control de Hato</title>
</head>
<body>
  <h1>Bienvenido a ProGanado</h1>
</body>
</html>
LíneaQué hacePor qué importa
<!DOCTYPE html>Le dice al navegador que el documento es HTML5.Sin esto, el navegador puede entrar en “modo quirks” y renderizar distinto.
<html lang="es">Envuelve todo el documento y declara el idioma.Ayuda a lectores de pantalla y a la traducción automática.
<head>Metadatos: cosas que no se ven en la página.Ahí van el título, la codificación, el viewport, los CSS y las fuentes.
<meta charset="UTF-8">Codificación de caracteres.Sin esto, los acentos y la ñ pueden salir como símbolos raros.
<meta name="viewport" ...>Le dice al móvil que use el ancho real del dispositivo.Es la base del diseño responsive; sin esto, el móvil “aleja” la página.
<title>Título de la pestaña del navegador.Es lo que ve el usuario en la pestaña y en los resultados de búsqueda.
<body>Todo lo visible.Aquí van las secciones, formularios, tablas e imágenes.
Analogía de la casa

HTML es la estructura de la casa: paredes, puertas, ventanas y habitaciones. CSS es la pintura, los muebles y la decoración. JavaScript es la electricidad y los automatismos (la puerta que se abre sola, el carrusel que cambia de foto). Bootstrap es un kit de muebles prefabricados que ya vienen con medidas estándar.

2.2 Etiquetas semánticas: el esqueleto con significado

Una etiqueta semántica no solo dice “caja”: dice qué papel cumple esa caja dentro de la página. Eso ayuda al navegador, a Google y a los lectores de pantalla.

EtiquetaQué representaEjemplo en ProGanado
<header>Encabezado de la página o de una sección.Barra superior con el logo, el nombre y el badge “SaaS 2026-2”.
<nav>Bloque de enlaces de navegación.Menú con Inicio, Panel, Métricas, Inventario, Galería, Sanidad, Potreros.
<main>Contenido principal y único de la página.Todo el contenido entre el navbar y el footer.
<section>Agrupación temática con un título.“Panel de Inicio”, “Métricas”, “Inventario”, “Galería”, “Sanidad”.
<article>Contenido independiente y autónomo.Una ficha de bovino o una noticia del hato; en el dashboard se usa poco.
<aside>Contenido complementario o lateral.Un resumen de alertas o una nota al lado del contenido principal.
<footer>Pie de página o de sección.Copyright, equipo desarrollador y ubicación.
<figure> / <figcaption>Imagen con su pie descriptivo.Foto de una vaca con su arete y una leyenda.

¿div o section? La regla práctica

<div> — caja genérica

No significa nada por sí sola. Se usa para agrupar y maquetar: una fila, una columna, un contenedor de botones. Es la caja de cartón: sirve para organizar, pero no dice qué hay dentro.

<div class="row g-4">
  <div class="col-lg-4">...</div>
</div>

<section> — sección con tema

Agrupa contenido relacionado y tiene un título (normalmente un h2). Si el bloque podría aparecer en el índice de la página, es una sección.

<section id="inventario">
  <h2>Inventario General del Hato</h2>
  <div class="row g-4">...</div>
</section>
La regla que debes poder decir

“Usamos section cuando el bloque tiene un tema y un título; usamos div cuando solo necesitamos una caja para organizar el layout. Bootstrap usa muchos div porque sus clases son presentacionales; nosotros procuramos que las regiones grandes de la página sean semánticas: header, nav, main, section y footer.”

El esqueleto de la página hecha a mano

<body>
  <header class="site-header">
    <nav class="navbar navbar-expand-lg">...</nav>
  </header>

  <main>
    <section id="inicio" class="hero-wrapper">...</section>
    <section id="funciones" class="py-5">...</section>
    <section id="datos" class="py-5 bg-light">...</section>
  </main>

  <footer class="site-footer">...</footer>
</body>

Ese esqueleto se lee de arriba a abajo y se entiende sin CSS. Esa es la prueba de una buena estructura HTML: si le quitas los estilos, la página sigue teniendo sentido.

¿Para qué se usa?Identificar un elemento único: un label for, un ancla (href="#inventario"), un hook de JavaScript, un “saltar al contenido”.Agrupar elementos con el mismo estilo o comportamiento: botones, tarjetas, columnas, utilidades de Bootstrap.

Tres atributos que parecen lo mismo pero no lo son
  • id: identifica el elemento en el DOM. Lo usa el label for, el CSS con # y JavaScript con getElementById.
  • class: agrupa elementos para estilo o comportamiento. Se separa con espacios: class="btn btn-success btn-lg" son tres clases.
  • name: es la llave con la que el dato viaja al servidor. Si un input no tiene name, no se envía en el formulario. En el formulario SQLite, name="arete" es lo que Python lee como datos["arete"].

Ejemplo real: el login

<label for="inputUsuario" class="form-label">Usuario o Correo</label>
<input type="text" class="form-control" id="inputUsuario" name="usuario"
       placeholder="Ej: profesor@cesde.edu.co">

<label for="inputPassword" class="form-label">Contraseña</label>
<input type="password" class="form-control" id="inputPassword" name="password"
       placeholder="Cualquier clave">

Lectura: el label for="inputUsuario" apunta al id="inputUsuario"; al hacer clic en la etiqueta, el cursor salta al campo. La clase form-control es de Bootstrap y le da el estilo. El name="usuario" es lo que el servidor recibiría si el formulario se enviara con POST.

2.5 Formularios: la puerta de entrada de los datos

Un formulario es la forma en que el usuario entrega información. En ProGanado hay tres: el login, el modal de registro de bovinos y el formulario real de SQLite.

Anatomía de un formulario

<form action="/guardar" method="POST">
  <fieldset>
    <legend>Datos del bovino</legend>

    <label for="arete">Arete</label>
    <input type="text" id="arete" name="arete" required maxlength="20"
           placeholder="Ej: COL-1601">

    <label for="peso">Peso (kg)</label>
    <input type="number" id="peso" name="peso_kg" required min="1" step="0.1">

    <label for="estado">Estado</label>
    <select id="estado" name="estado">
      <option value="Activo">Activo</option>
      <option value="En tratamiento">En tratamiento</option>
      <option value="Vendido">Vendido</option>
    </select>

    <button type="submit" class="btn btn-success">Guardar</button>
  </fieldset>
</form>
ElementoQué hacePor qué se usa
<form>Envuelve los controles y define action y method.Sin action, el formulario se envía a la misma página; sin method, usa GET.
<fieldset> / <legend>Agrupan controles relacionados y dan un título al grupo.Mejora la accesibilidad y la lectura visual.
<label for="...">Etiqueta del campo; el for debe coincidir con el id.Al tocar la etiqueta se enfoca el campo; los lectores de pantalla lo anuncian.
<input>Campo de una línea; el type define el comportamiento.Texto, email, número, fecha, contraseña, etc.
<select> / <option>Lista desplegable y sus opciones.Para estados, razas, tipos de documento.
<textarea>Texto de varias líneas.Observaciones, notas del veterinario.
<button type="submit">Envía el formulario.El tipo submit es el que dispara el envío.

Parte 3 · CSS desde cero

CSS (Cascading Style Sheets) es el lenguaje que decide cómo se ve el HTML: colores, tamaños, espacios, bordes, tipografía, posición y comportamiento en pantallas pequeñas. HTML dice qué es; CSS dice cómo se ve.

Si nuestro CSS va antes que Bootstrap, Bootstrap puede ganarle en las reglas que empatan en especificidad. La regla práctica: Bootstrap primero, lo propio después. Si aun así no gana, no uses !important a la locura: revisa la especificidad o usa una clase más específica.

Lo que vimos en clase

El profesor insistió en separar responsabilidades: HTML para la estructura, CSS para la presentación. 3.3 El modelo de caja

Todo elemento HTML es una caja rectangular compuesta por cuatro capas. Entender esto explica el 80% de los problemas de espaciado.

+-----------------------------------+
|              margin               |
|   +---------------------------+   |
|   |          border           |   |
|   |   +-------------------+   |   |
|   |   |      padding      |   |   |
|   |   |   +-----------+   |   |   |
|   |   |   | contenido |   |   |   |
|   |   |   +-----------+   |   |   |
|   |   +-------------------+   |   |
|   +---------------------------+   |
+-----------------------------------+
CapaQué esPropiedad
ContenidoTexto, imagen o video.width, height
PaddingEspacio interno, entre el contenido y el borde.padding
BordeLínea que rodea el padding.border
MargenEspacio externo, entre esta caja y las demás.margin

content-box vs border-box

Por defecto, CSS usa content-box: si defines width: 500px y luego padding: 34px y border: 1px, la caja real mide 500 + 68 + 2 = 570px. Con border-box, los 500px incluyen padding y borde: la caja mide 500px y el contenido se ajusta. Bootstrap aplica border-box a todo:

*, *::before, *::after {
  box-sizing: border-box;
}

.login-card {
  width: 500px;      /* con border-box, esto es el ancho total */
  padding: 34px;     /* el contenido se reduce, la caja no crece */
  border: 1px solid rgba(255,255,255,.28);
}
Si preguntan “¿por qué la caja mide más de lo que pediste?”

“Porque el modelo por defecto es content-box: el ancho que declaras es solo el contenido, y el padding y el borde se suman. Con box-sizing: border-box, el ancho declarado incluye padding y borde, que es lo que hace Bootstrap y lo que usamos en el proyecto.”

  • padding da aire dentro de la caja; margin separa cajas.
  • Los márgenes verticales entre hermanos pueden colapsar (se superponen); si necesitas una separación exacta, usa gap en un contenedor Flexbox o padding.
  • Bootstrap: mx-auto centra horizontalmente; my-4 da margen vertical; p-3 da padding; gap-2 separa hijos de un flex.

El error clásico del z-index

“Le puse z-index: 9999 y no funciona.” Casi siempre es porque el elemento es position: static o porque un padre creó un contexto de apilamiento con un z-index menor. Primero revisa la posición y el árbol de ancestros; después sube el número.

¿Qué es exactamente backdrop-filter?

Es una propiedad que aplica un filtro a lo que está detrás del elemento, no a su contenido. blur(22px) desenfoca el fondo; saturate(1.2) aumenta un 20% la saturación. Por eso la foto se ve “derretida” a través de la tarjeta. Sin transparencia en el fondo de la tarjeta, el efecto no se nota: las dos piezas trabajan juntas.

Fallback para navegadores que no lo soportan

@supports not (backdrop-filter: blur(1px)) {
  .login-card {
    background: rgba(12, 28, 20, .94); /* más opaco, sin blur */
  }
}

@supports pregunta si el navegador entiende una propiedad. Si no entiende backdrop-filter, la tarjeta se vuelve casi opaca para que el texto siga siendo legible. Es una buena práctica de ingeniería: el efecto es un lujo, la legibilidad es obligatoria.

Parte 4 · Bootstrap: instalación y uso

Bootstrap es un framework de CSS y JavaScript que trae componentes y utilidades ya probados: navbar, carrusel, tarjetas, modales, tablas, formularios, botones y un sistema de 12 columnas. No es un lenguaje nuevo: es una hoja de estilos enorme llena de clases que se aplican al HTML.

4.1 Qué es y qué no es Bootstrap

Sí es

  • Un conjunto de clases CSS listas para usar.
  • Un conjunto de componentes con HTML + CSS + JavaScript.
  • Un sistema de grid de 12 columnas y breakpoints.
  • Una documentación oficial con ejemplos copiables.

No es

  • Una base de datos.
  • Un lenguaje de programación.
  • Un sistema de autenticación.
  • Una garantía de accesibilidad automática.
  • Un reemplazo del HTML semántico.

4.10 Lo que Bootstrap no resuelve

  • Datos: Bootstrap no guarda nada; para eso está SQLite y el servidor Python.
  • Autenticación: el login visual no valida usuarios reales; eso requiere backend, hash de contraseña y sesiones.
  • Semántica: puedes hacer una página horrible de accesibilidad con Bootstrap si no usas alt, label, jerarquía de títulos y foco visible.
  • Contenido: los textos, las fotos y la historia son del proyecto; el framework no los inventa.
  • Rendimiento: el CSS completo de Bootstrap pesa; en producción se personaliza y se importa solo lo necesario.

5.1 Qué es Tailwind CSS

Tailwind es un framework utility-first: en lugar de darte componentes con nombres como card o navbar, te da cientos de clases pequeñas que aplican una sola propiedad CSS. Tú compones el diseño directamente en el HTML.

<div class="flex items-center justify-between gap-4 rounded-xl bg-white p-6 shadow-lg">
  <h2 class="text-lg font-bold text-slate-900">Inventario</h2>
  <button class="rounded-lg bg-emerald-600 px-4 py-2 text-white hover:bg-emerald-700">
    Registrar
  </button>
</div>

Ese bloque no usa una clase “card”: usa flex, items-center, justify-between, gap-4, rounded-xl, bg-white, p-6, shadow-lg. Cada clase hace una cosa. El resultado es un diseño a medida, pero el HTML se llena de nombres.

5.2 Cómo se instala Tailwind (conceptual)

Tailwind tiene dos caminos:

FormaCómoUso
Play CDN<script src="https://cdn.tailwindcss.com"></script>Pruebas y experimentos. No se recomienda para producción.
CLI / buildnpm install -D tailwindcss @tailwindcss/cli; un archivo de entrada; un comando que genera el CSS final.Producción: genera solo las clases que se usan y permite configuración de tema.
 
# Ejemplo conceptual de instalación con CLI (no ejecutado en el proyecto)
npm install -D tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i ./src/input.css -o ./dist/output.css --watch
/* src/input.css — según la versión de Tailwind */
@import "tailwindcss";

/* o, en versiones anteriores:
@tailwind base;
@tailwind components;
@tailwind utilities;
*/

El comando --watch observa los archivos y regenera el CSS cuando cambias una clase. Sin ese paso, las clases nuevas no existen en el CSS final. Es la diferencia práctica más grande con Bootstrap: Bootstrap ya viene con todo; Tailwind se construye a la medida.

5.4 Pros y contras

Bootstrap

Pros: componentes listos, grid claro, documentación enorme, no exige build, el profesor lo enseñó, equipo puede defenderlo rápido.

Contras: look reconocible, personalización puede requerir CSS extra, el archivo completo pesa, algunas decisiones de diseño vienen impuestas.

Tailwind

Pros: control total del diseño, CSS final pequeño, utilidades consistentes, no impone componentes, buena para sistemas de diseño.

Contras: HTML con muchas clases, no hay componentes listos, requiere build, curva de aprendizaje, más difícil de defender sin práctica.

5.5 Por qué elegimos Bootstrap

  1. Se vio en clase. El profesor enseñó Bootstrap 6 alpha el 17-oct; Tailwind no se dictó.
  2. El equipo es principiante. Los componentes listos permiten avanzar sin diseñar cada detalle desde cero.
  3. No exige build. Un CDN o una carpeta local bastan; no hay que configurar Node, CLI ni un pipeline.
  4. Se puede defender. Cada componente tiene documentación oficial y un nombre claro; el equipo puede explicar qué hace cada clase.
  5. Estabilidad. Usamos 5.3.3 estable, no una alpha; el proyecto no cambia bajo los pies.
  6. Tiempo. La exposición es en noviembre; Bootstrap ahorra horas de CSS y permite concentrarse en la conexión SQLite y en la auditoría de IA.
Si preguntan “¿por qué no Tailwind?”

“Tailwind es excelente para un diseño a medida, pero exige un paso de compilación y componer cada utilidad; nuestro equipo está aprendiendo las bases y el profesor enseñó Bootstrap. Elegimos la herramienta que nos permitía entender y defender cada línea, no la que estaba de moda. Estudiamos Tailwind conceptualmente y podemos explicar la diferencia: Bootstrap te da el componente; Tailwind te da las piezas para construirlo.”

Parte 8 · SQLite: conexión real

Esta es la parte que más impresiona y la que más se puede explicar mal. SQLite no es un servidor: es una base de datos que vive en un archivo. El formulario envía datos, Python los valida, SQLite los guarda y la página los vuelve a leer. Ese ciclo es el corazón de la demo.

8.1 Qué es SQLite y por qué lo elegimos

PreguntaRespuesta corta
¿Qué es?Una base de datos relacional que se guarda en un solo archivo (proganado.db).
¿Necesita instalar un servidor?No. Python ya trae el módulo sqlite3; no hay que instalar MySQL, SQL Server ni PostgreSQL.
¿Dónde están los datos?En el archivo proganado.db, en la misma carpeta del proyecto.
¿Sirve para producción?Para una demo y para un sistema de un solo usuario, sí. Para varios usuarios concurrentes en red, conviene un motor cliente-servidor.
¿Por qué lo elegimos?Porque es local, no necesita internet, se explica en una tarde y demuestra el ciclo completo de datos sin montar un backend complejo.
¿Qué relación tiene con SQL?SQLite entiende SQL: CREATE TABLE, INSERT, SELECT, UPDATE, DELETE, WHERE, ORDER BY.

8.3 init_db.py: crear la base y los datos de ejemplo

import sqlite3
from pathlib import Path

DB = Path(__file__).with_name("proganado.db")


def main():
    with sqlite3.connect(DB) as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS bovinos (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                arete TEXT NOT NULL UNIQUE,
                nombre TEXT NOT NULL,
                raza TEXT NOT NULL,
                fecha_nacimiento TEXT,
                peso_kg REAL NOT NULL CHECK (peso_kg > 0),
                estado TEXT NOT NULL DEFAULT 'Activo'
                    CHECK (estado IN ('Activo', 'En tratamiento', 'Vendido')),
                creado_en TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))
            )
        """)
        conn.executemany(
            """
            INSERT OR IGNORE INTO bovinos
                (arete, nombre, raza, fecha_nacimiento, peso_kg, estado)
            VALUES (?, ?, ?, ?, ?, ?)
            """,
            [
                ("COL-1601", "Estrella", "Holstein", "2022-03-14", 520.5, "Activo"),
                ("COL-1599", "Mora", "Normando", "2021-11-02", 480.0, "En tratamiento"),
                ("COL-1603", "Gitana", "Jersey", "2023-01-20", 410.3, "Activo"),
            ],
        )
    print(f"Base lista en: {DB}")


if __name__ == "__main__":
    main()

Lectura línea por línea:

  • Path(__file__).with_name("proganado.db"): la base queda en la misma carpeta del script, sin rutas absolutas.
  • with sqlite3.connect(DB) as conn: abre la conexión y confirma los cambios al salir del bloque.
  • CREATE TABLE IF NOT EXISTS: se puede ejecutar varias veces sin borrar lo que ya existe.
  • INSERT OR IGNORE: inserta los datos de ejemplo; si el arete ya existe, no falla.
  • Los ? son parámetros: los valores van aparte, no concatenados en el SQL.

    if not raza:

    if estado not in ESTADOS:
        errores.append("El estado no es válido.")

        if peso <= 0:

        errores.append("El peso debe ser un número.")

            datetime.strptime(fecha, "%Y-%m-%d")
        except ValueError:
            errores.append("La fecha debe tener el formato AAAA-MM-DD.")

class Handler(BaseHTTPRequestHandler):
    def _enviar(self, codigo, contenido, tipo="text/html; charset=utf-8"):
        data = contenido.encode("utf-8")
        self.send_response(codigo)
        self.send_header("Content-Type", tipo)
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)

    def do_GET(self):
        partes = urlparse(self.path)
        if partes.path == "/favicon.ico":
            self.send_response(204)
            self.end_headers()
            return
        if partes.path not in ("/", "/index.html"):
            self._enviar(404, "<h1>404 — Ruta no encontrada</h1>")
            return
        qs = parse_qs(partes.query)
        q = qs.get("q", [""])[0]
        estado = qs.get("estado", [""])[0]
        mensaje = "Bovino guardado correctamente." if qs.get("ok") else ""
        self._enviar(200, render(listar(q, estado), q=q, estado=estado, mensaje=mensaje))

    def do_POST(self):
        if urlparse(self.path).path != "/guardar":
            self._enviar(404, "<h1>404 — Ruta no encontrada</h1>")
            return
        largo = int(self.headers.get("Content-Length", 0))
        if largo <= 0:
            self._enviar(400, "<h1>400 — Formulario vacío</h1>")
            return
        datos = parse_qs(self.rfile.read(largo).decode("utf-8"))
        datos = {k: v[0] for k, v in datos.items()}
        errores = insertar(datos)
        if errores:
            self._enviar(200, render(listar(), errores=errores))
            return
        self.send_response(303)
        self.send_header("Location", "/?ok=1")
        self.end_headers()

    def log_message(self, fmt, *args):
        print(f"[{self.address_string()}] {fmt % args}")

SQLite no distingue mayúsculas en los nombres de tablas por defecto, pero usar minúsculas y snake_case evita confusiones entre sistemas operativos y hace que el SQL sea más portable. Es una convención, no una obligación del motor.

8.9 El ciclo completo, paso a paso

1. El usuario llena el formulario en plantilla.html.
2. El navegador envía POST /guardar con los campos name="...".
3. servidor.py lee el cuerpo, parsea los campos y llama a insertar().
4. insertar() valida y ejecuta:
   INSERT INTO bovinos (...) VALUES (?, ?, ?, ?, ?, ?)
5. SQLite escribe la fila en proganado.db.
6. El servidor responde 303 y redirige a /?ok=1.
7. El navegador hace GET /.
8. listar() ejecuta SELECT ... WHERE ... ORDER BY id DESC.
9. render() reemplaza {{FILAS}} con las filas escapadas.
10. El navegador recibe la tabla actualizada.

Ese ciclo es el mismo que hace cualquier aplicación web, solo que con piezas más grandes (framework, ORM, servidor de producción). Entenderlo en pequeño es la base para entenderlo en grande.

9.5 Reflexión ética: seis principios

  1. La IA es una herramienta, no la autora. Nos ayuda a prototipar, revisar y explicar; la responsabilidad del producto es humana.
  2. Verificar antes de aceptar. Una sugerencia sin prueba es una opinión. La evidencia es el navegador, la documentación y el test.
  3. No usar datos personales en los prompts. No pegamos cédulas, teléfonos, correos ni contraseñas. Para ejemplos, usamos datos sintéticos.
  4. Declarar el uso de IA. En la exposición decimos qué hicimos con IA y qué hicimos nosotros. No ocultamos el proceso.
  5. No plagiar ni falsear. No presentamos como propio un código que no entendemos; no inventamos datos de la finca ni resultados.
  6. El usuario final importa. La IA puede acelerar una interfaz, pero la accesibilidad, la privacidad y la seguridad son decisiones humanas.
La frase que resume la ética del proyecto

“Usamos la IA para pensar mejor, no para pensar menos. Nos ayudó a llegar rápido a un prototipo y a revisar el código; el criterio, la verificación y la responsabilidad fueron nuestros. Por eso podemos explicar cada línea que mostramos.”
